# Trion — Deployment

## Prerequisites

- Docker (with Compose plugin v2) or Node.js 18+
- Python 3.11+ (for trion-agent only)
- A Supabase project (free tier works)
- At least 1 GB RAM — Raspberry Pi 5 or any equivalent

---

## Quick start

```bash
git clone https://github.com/S2K7x/Trion
cd Trion
./install.sh
```

The interactive script detects available tools, prompts for environment variables, applies the Supabase schema, and starts services.

**Non-interactive flags:**

```bash
./install.sh --mode dev          # Next.js dev server + n8n in Docker
./install.sh --mode full         # Everything in Docker Compose
./install.sh --mode full --skip-db   # Skip schema if already applied
./install.sh --env /path/.env    # Use a specific .env file
```

## Deployment modes

### `docker-compose.yaml` — n8n dev (default)

Single n8n container using SQLite. Used by `--mode dev` and `--mode prod` to run n8n locally alongside a Node.js dashboard. Suitable for development and single-machine deployments.

```bash
docker compose up -d
```

### `docker-compose.full.yaml` — Dashboard + n8n

Runs both the Next.js dashboard (built from `Dockerfile`) and n8n in Docker Compose. Database remains on Supabase cloud. Used by `--mode full` and `--mode docker`.

```bash
docker compose -f docker-compose.full.yaml up -d --build
```

### `docker-compose.n8n-prod.yaml` — n8n production

Production-grade n8n deployment for Raspberry Pi or a dedicated server. Adds PostgreSQL (persistent n8n database), Redis (execution queue), a dedicated n8n worker container, and a Cloudflare tunnel for public webhook exposure without port forwarding. Requires `.env` filled from `.env.n8n.example`.

```bash
cp .env.n8n.example .env
# fill .env with DB credentials, Redis password, Cloudflare tunnel token
docker compose -f docker-compose.n8n-prod.yaml up -d
```

### `docker-compose.wazuh.yaml` — Wazuh stack reference

Reference configuration for Wazuh 4.9 single-node deployment (manager + indexer + dashboard). **Requires TLS certificates generated before first launch** — follow the Wazuh Docker documentation. Provided as a reference; adapt passwords before any production use.

```bash
# Certificate generation (from wazuh-docker repo, not this repo)
git clone https://github.com/wazuh/wazuh-docker.git
cd wazuh-docker && git checkout v4.9.0 && cd single-node
docker compose -f generate-indexer-certs.yml run --rm generator
docker compose up -d
```

## Environment variables

Copy `.env.example` to `.env.local` and fill in all values.

```bash
cp .env.example .env.local
```

| Variable | Description |
|----------|-------------|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase anon key (public) |
| `SUPABASE_SERVICE_KEY` | Supabase service_role key — **server-side only, never expose to client** |
| `DASHBOARD_PASSWORD` | Dashboard login password |
| `DASHBOARD_SECRET` | JWT signing secret — min 32 chars (`openssl rand -hex 32`) |
| `N8N_API_URL` | n8n instance URL (`http://localhost:5678`) |
| `N8N_API_KEY` | n8n API key (Settings → API in n8n UI) |

`DASHBOARD_SECRET` is auto-generated by `install.sh` if `openssl` is available.

`N8N_API_KEY` is optional at first launch — workflow status cards show "unreachable" until it is set.

## Supabase schema

Run [`supabase/migrations/001_init.sql`](../supabase/migrations/001_init.sql) once in the Supabase SQL Editor. It creates the `alert_queue` table and the four RPC functions used by the dashboard.

If the Supabase CLI is installed and the project is linked, `install.sh` applies the migration automatically via `supabase db push`.

## Vercel deployment (dashboard only)

1. Push to GitHub
2. Import on [vercel.com](https://vercel.com) — Next.js is auto-detected
3. Add the 7 environment variables in Project Settings → Environment Variables
4. Deploy

`vercel.json` is already configured. No custom build command required.

> If your n8n instance is not publicly reachable, workflow status cards show "unreachable" — the rest of the dashboard works normally.

## n8n workflow import

Import the three workflows from [`n8n_workflows/`](../n8n_workflows/) into your n8n instance via Settings → Import Workflow.

| File | Workflow |
|------|----------|
| `soc-ingest.json` | Wazuh alert ingestion |
| `soc-triage.json` | IOC enrichment + Slack notification |
| `soc-error-handler.json` | Error retry |

After import, activate all three workflows and set the `N8N_API_KEY` in your `.env.local`.
